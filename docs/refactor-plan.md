# Split_kMeans refactor plan (v2.0.0)

Goal: correct, reproducible, fast and maintainable split k-means experiments for the master's thesis, and the final thesis results in the format of the approved seminar presentation.

Rules: refactors keep golden outputs bit-identical. Algorithm changes are one commit each, with `make golden-update`, a changelog entry and before/after statistics. Code comments are unverified claims, not a source: the code defines current behavior, the primary literature or your decision defines intended behavior. Milestones M0 to M4 (below) check real data at fixed points. Thesis times come only from release builds at log level 1 on one reference machine (D3), taken from `<Algo>_runs.csv`.

Build target for the professor: `make && make check` in the repo root (Linux). Visual Studio 2026 project kept in `msvc/`. Supported platforms: Linux and Windows (MinGW-w64, Visual Studio 2026). macOS is not supported (see Open decisions).

Default settings (professor's requirement): the exe runs with no arguments (batch mode) and with `-k K data.txt [gt.txt]`. Every new option defaults to today's behavior; `make check` smoke-tests both invocations.

Thesis results (seminar presentation approved by the thesis supervisor, 18.06.2025; local copies: `university/course/out/md/Seminaari_180625.md`, v1 data in `university/excels/`): SKM-Intra, SKM-Global and SKM-Local against RKM, RS, bisecting k-means and Split-PCA on the local SIPU sets (19 today; more DIM sets follow, D6); measures time, SSE, CI and success rate. Deliverables: tables of average CI, success rate and time (algorithms × datasets, slides 53 to 55); per-dataset graphs of SSE and CI against time on a log scale (RS and RKM as curves, the other algorithms as end points; slide 50 and `seminaari_TimeGraphs – KM.xlsx`); MATLAB cluster figures from snapshots (`visuals/generalizedplotting.m`). RS results (tables and graphs) end at the first CI = 0 of each run (the thesis supervisor's requirement, 2026-11-19); the program logs every run to its end and only `report` (3.9) cuts the RS results. The v1 graphs that the thesis supervisor accepted used one RS run and one RKM run per dataset, both drawn to the end of the run (all 19 graph sheets; RKM over its 1000 repeats, RS past its first CI = 0, for example S4: CI = 0 at 44 ms, line to 7591 ms); v2 keeps that format, except that the RS curve now ends at CI = 0 and RKM still runs to the end. Split-PCA results are copied by hand from CBModules runs (integration: Future work F1).

Milestones (real data, seed 20261119, one release build (MinGW gcc, the expected thesis build until 5.1 confirms it, D3), log level 1, run folders outside OneDrive, summaries in `results/` (D4)): s1, s4, a3, unbalance, dim064 and worms_2d (worms_2d without SKM-Global, RKM and RS); algorithms km, skm-intra, skm-global, skm-local, bisecting, rkm and rs; development budget (D1): 100 runs on the five small sets, 10 on worms_2d, RKM and RS 1 run; about 10 minutes at v1 speed, half of it RKM. Until 3.3 they run in CLI mode, because batch mode writes tracking rows inside the timed code. M1, M2, M3a and M3b must reproduce the SSE and CI of M0 (M3b: of the last M4) exactly with `compare_runs`, which also covers the last-bit changes that the integer golden data cannot see; any run count is an exact check. M4 runs before and after each Phase 6 step, with only the algorithms the step changes.
